# NF26 – BGES Project

Academic project for the **NF26** course (UTC, GI04) implementing a data pipeline and analytics dashboard for a fictional multinational company's **BGES** (*Bilan des Gaz à Effet de Serre* — Greenhouse Gas Assessment). The project ingests daily raw HR, IT equipment, and business-travel data from six international sites, builds a clean star-schema data warehouse, and answers a set of carbon-impact business questions through both a Jupyter notebook and an interactive dashboard.

## Overview

The fictional organization operates sites in **Paris, London, Berlin, New York, Los Angeles, and Shanghai**. Each site produces daily raw data drops for:

- **Personnel** — employee records (role, birth date, address, etc.)
- **Materiel Informatique** — IT equipment purchases (type, model, purchase date)
- **Mission** — business trips (origin/destination, transport mode, dates)

The goal is to consolidate this multi-site, multi-language, messy raw data into a clean relational model and compute the carbon footprint (in tCO₂e) generated by IT equipment and business travel, broken down by site, role, time period, and other dimensions.

## Data pipeline (ETL)

The ETL is implemented in [ETL.ipynb](ETL.ipynb) using **PySpark** (`pyspark.pandas`) and runs as a daily batch simulated over the period **2026-04-29 to 2026-11-14**:

1. **Extract** — reads the day's raw `PERSONNEL_*.txt`, `MATERIEL_INFORMATIQUE_*.txt`, and `MISSION_*.txt` files across all sites, and joins equipment purchases with their reference carbon impact.
2. **Transform**
   - Uniformizes job roles and mission types across languages (French, German, English) via mapping dictionaries.
   - Cleans and imputes missing IT equipment types (majority-vote by model, with a global fallback).
   - Geocodes cities with **Nominatim** (via `geopy`) and caches coordinates (`TABLES/CACHE_COORD.csv`) to avoid repeated lookups.
   - Resolves each country's continent using `country_converter`, translating country names with `deep_translator` when needed, and caches the results (`TABLES/CACHE_PAYS_CONTINENT.csv`).
   - Computes trip distance (Haversine formula) and the resulting carbon impact per mission, with coefficients depending on the mode of transport (plane, train, taxi, public transport) and flight distance bracket.
3. **Load** — appends only new rows (diffed against existing CSVs) into the star-schema tables under [TABLES/](TABLES/).
4. **Logging** — every run logs each step and any errors to `logs/etl_<date>.log`.

## Data model

The warehouse follows a star schema (see [database.drawio](database.drawio)):

- **Dimensions**: `PERSONNEL`, `SITE`, `DATE`, `LOCALISATION`, `MATERIEL_INFORMATIQUE`, `MISSION`
- **Facts**: `FAITS_MATERIEL_INFORMATIQUE` (links personnel ↔ equipment purchases), `FAITS_MISSION` (links personnel ↔ business trips)

## Analysis and dashboard

- [projet.ipynb](projet.ipynb) contains the exploratory analysis and the queries answering the project's 20 business questions (headcounts by role/site, carbon impact by equipment/transport/period, most impactful sites/sectors/destinations, etc.). Final results are summarized in [rendu_pdf.md](rendu_pdf.md).
- [dashboard.py](dashboard.py) is a **Streamlit** app (with **Plotly** charts) that lets users filter by site, month range, and job role to explore missions/equipment carbon impact interactively, including several of the project's key figures (top impactful missions, monthly impact by transport mode and site, global monthly impact).

## Getting started

### Requirements

The ETL relies on PySpark and several enrichment libraries; the dashboard relies on Streamlit/Plotly. Install what you need depending on which part you run:

```bash
pip install pyspark pandas numpy deep-translator country_converter geopy jupyter matplotlib plotly streamlit
```

### Running the ETL

Open and run [ETL.ipynb](ETL.ipynb) in Jupyter. It will (re)build the `TABLES/` CSV files from the raw data in `BDD_BGES/` and write logs to `logs/`.

### Exploring the analysis

Open [projet.ipynb](projet.ipynb) in Jupyter to review the queries and visualizations behind each answer in [rendu_pdf.md](rendu_pdf.md).

### Running the dashboard

```bash
streamlit run dashboard.py
```

This reads the pre-built tables from `TABLES/`, so run the ETL first if that folder is empty or stale.
